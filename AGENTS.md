# AGENTS.md

Workspace-wide rules live in `~/projects/AGENTS.md`; this file adds rules
specific to this Hugo site. See `README.md` for what the site is.

## Layout

- `hugo.toml` is the active config; the active theme is `beautifulhugo`.
- `content/` holds the site pages. Blog posts are `content/blog/YYYY-MM-DD.md`.
- `layouts/` holds site-level overrides (e.g. `layouts/partials/comments.html`).
- `data/comments/*.json` is generated by `export_comments.py` from a Google
  Sheet of form responses; one file per page slug.
- `themes/beautifulhugo/` and `themes/hugo-clarity/` are vendored copies, not
  submodules.
- `config-beautifulhugo/` and `config-hugo-clarity/` are alternative theme
  configs, not used by the default build.
- `hugo-config.txt`, `hugo-gen-doc/` and `man/` are saved output from
  `hugo config` / `hugo gen doc` / `hugo gen man`, kept as local reference.
  The site build does not use them.

## Do not modify

- `themes/**`: override in the site's `layouts/` instead of editing the theme.
- `hugo-gen-doc/`, `man/`, `hugo-config.txt`: regenerate rather than hand-edit.
- `data/comments/*.json`: regenerate with `make export-comments`, which needs
  `GOOGLE_SERVICE_ACCOUNT_KEY_FILE`; confirm before running it.
- Existing post `date` and filenames: they form published URLs.
- Never commit `public/`, `resources/_gen/`, `logs/*`, or service-account keys.

## Commands

Run `make help` for all targets. Key ones:

- `make check`: doctor, lint, types, test and a production build. Run before
  committing.
- `make build`: production build into `public/`.
- `make serve`: local dev server including drafts and future posts.
- `make new CONTENT=blog/YYYY-MM-DD.md`: new post from `archetypes/default.md`.
- `make lint` / `make format` / `make types`: Ruff and basedpyright on
  `export_comments.py`. Add new Python files to `PYTHON_SOURCES` in the
  `Makefile` and `include` in `pyproject.toml`.

## Conventions

- New posts start with `draft: true`; leave the draft flag alone unless asked
  to publish.
- Use British English (`locale = 'en-GB'`) in site content.
- Follow `.editorconfig`: 2-space indent, 4 spaces for Python.
- Pushing to `main` deploys to GitHub Pages via
  `.github/workflows/hugo.yaml`, which pins `HUGO_VERSION`. Treat a push as a
  publish and confirm first. Keep the pinned version compatible with local
  Hugo when changing either.
